# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Internal operational tool for Energisa's COI (Centro de Operação Integrado) — a single-page "app" used by call-center staff to send standardized/personalized WhatsApp messages to customers (callback) and to access a handful of static utility references (regional maps, contractor map, technical tables) and external links (shift schedule, shift handover form). Pure static HTML/CSS/JS, no backend, no build tooling, no package manager. This directory **is** a git repository (`refactor/sistema-ferramentas` branch, off `main`) — commit locally as normal, but see the "Project status" section below for what must not happen yet.

## Running / previewing

There is no install or build step. Open `index.html` directly in a browser (or serve the folder with any static file server). All persistence is `localStorage`; there is no server component.

There is no test suite or linter. To sanity-check an edit without a browser:
- `node -c js/<file>.js` — validates JS syntax (catches broken template literals, stray tags pasted into a `.js` file, etc.)
- A quick Node one-liner to confirm CSS brace balance after editing `styles.css` / `css/callback-whatsapp.css`, e.g. counting `{` vs `}` — useful because the CSS has no build step to catch a mismatched brace.
- Grep for specific `id="..."`, `class="..."`, and `onclick="..."` strings before/after an edit to confirm nothing referenced by JS was renamed.

## ESTADO ATUAL (implementado e funcionando)

**Single-page shell, module-per-screen.** `index.html` contains each real screen as a `<div id="X" class="module">`. Only the module with `.active` is visible (`display:none` otherwise). `openModule(id, btn)` (defined in `js/core.js`) swaps the `.active` class on both the target `.module` and the clicked sidebar `<button>`. There is no router/URL state — refreshing the page always returns to the default module (`#inicio`, marked `active` in the HTML).

**Current modules / sidebar entries:**
- **Início** (`#inicio`) — placeholder welcome screen. No functionality yet; this is where the future home/dashboard will live.
- **Callback WhatsApp** (`#callback`) — the one fully-functional module. See below.
- **Central Callback Web** (ATENDIMENTO) — not an internal module; the sidebar button calls `abrirCentralCallback()` (inline in `index.html`), which opens `https://thiagoshield199403-svg.github.io/central-callback/` in a new tab via `window.open(url, "_blank", "noopener,noreferrer")`.
- **Mapa de Empreiteira** — same modal mechanism, single image (`mapas/mapa_empreiteiras.jpg`), triggered directly from the sidebar button (no dedicated `.module`).
- **Tabelas Técnicas** — opens `#modalTabela` (a plain `.modal` div, not a `.module`) via `abrirTabela()`/`fecharTabela()`, defined inline in `index.html`.
- **Escala** (GESTÃO) — not an internal module at all; the sidebar button calls `abrirEscala()` (inline in `index.html`), which opens the external schedule board (`https://adao175.github.io/Escala-operacional-coi-V2/`, GitHub Pages) in a new tab via `window.open(url, "_blank", "noopener,noreferrer")`.
- **Passagem de Turno** (GESTÃO) — not an internal module; the sidebar button calls `abrirPassagemTurno()` (inline in `index.html`), which opens the real Microsoft Power Apps shift-handover app in a new tab (`window.open(url, "_blank", "noopener,noreferrer")`). - **Presentation rule of the Mapa Regional Interativo (do not change without a new request):** ON THE MAP only the polo NUMBER (never municipality, bairro or locality names as permanent labels); LIST, TOOLTIP: "número — nome" (list in ascending codigo order within the regional); SIDE PANEL: "número — nome" + regional (+ IBGE). All 58 numbers show immediately when the module opens — there is NO code import, no JSON file, no "Restrito"/lock, no session/local storage for codes (that earlier mechanism was removed on 2026-11-14 when the project owner authorized versioning the codes). Association number ↔ territory is always by IBGE code. `mrPlanejarRotulos(itens, {k, limites})` (pure, tested) places the numbers in viewBox units with the font size thought in screen PIXELS (`k` = px per unit, `MR_ROTULO`: 12.5–21 px, proportional to the inscribed-circle radius): inside the territory at the pole of inaccessibility when it fits, otherwise an external badge ("chamada") with a discreet leader line to the territory — never hidden, cut or overlapping; IBGE geometry is never altered. `mrDesenharRotulos()` reruns on regional change and resize (ResizeObserver) — selection never moves numbers — and crops the viewBox to geometry+badges so the map uses the space. Single state `{regional, hover, selecionado}` drives map, list, tooltip and panel (pure functions `mrAoPassar/mrAoSair/mrAoClicar/mrLimparSelecao/mrTrocarRegional/mrMarcacao`); layers base → destaque → números so numbers stay visible on hover/selection; hovering/clicking the number or badge = the municipality. Keyboard: Tab to territories/list, Enter/Space selects, Esc clears, ←/→/Home/End switch regional tabs. A browser E2E (Chrome headless via CDP, no dependencies) lives OUTSIDE the repo in `../testes-locais-mapa-regional/`.

Sources (official IBGE only, documented in `geodata/ibge-2022/NOTICE.md`): Malha Municipal 2022, Malha de Bairros do Censo 2022 (109 bairros: Aracaju 48, Barra 18, Socorro 29 — two "Porto Grande" records —, São Cristóvão 14, Itaporanga 0) and Cadastro de Localidades Selecionadas 2010 (points, no boundary). Pipeline: original IBGE zips (kept OUTSIDE the repo in `../fontes-geograficas/`) → `node ferramentas/importar-ibge-2022.js ../fontes-geograficas` (uses `ferramentas/ler-shapefile.js`, no deps) → `geodata/ibge-2022/*.geojson` → `node ferramentas/gerar-mapa-expansao.js` → `js/mapa-regional/geometria-expansao.js` (GENERATED: per area municipios/bairros/localidades geometry, same projection rules) + `js/mapa-regional/subdivisoes.js` (GENERATED metadata: bairro id `b<IBGE bairro code>`, localidade id `l2010-<IBGE id>`, nome, municipio pai, fonte, delimitacao, `codigo: null` reserved, coverage % per municipality). Never hand-edit; tests fail if out of date. `geometria.js` (58 approved municipalities) is untouched and a test guarantees it is byte-identical when regenerated. Two levels: selecting a municipality (number on map, list row) highlights its whole territory + ALL its bairros in cyan (`mr-municipio-sel`, translucent `mr-destaque-com-bairros`, no scale); selecting a bairro/localidade highlights only it in orange (`mr-destaque-bairro`); clicking the selected item again or Esc clears (Esc listens on `document` while the module is active, because bairro polygons are not focusable). Bairro/locality names are NEVER written on the map (no text in those layers) — only list (expandable tree per municipality: `.mr-expandir` with `aria-expanded`, single-municipality areas open expanded), tooltip and panel; polo codes are never repeated on bairros. Localities are drawn as small dots (seat only where there are no bairros; none duplicating a bairro name). Zoom: wheel, drag (only when zoomed; a drag never becomes a click), +/−/fit buttons (`.mr-zoom`) and "Aproximar no mapa" in the panel; camera = viewBox window (`mrZoomJanela/mrMoverJanela/mrJanelaPara`, pure, max 16×); numbers are re-planned in pixels for the zoomed window. IMPORTANT: always query the map with `svg.mr-svg` — the palco also contains icon SVGs (zoom buttons). `geodata/aracaju/aracaju.geojson` (OpenStreetMap, used by the Mapa Operacional) is NOT used by this module and must not be changed.

`abrirTabela()`/`fecharTabela()` (Tabelas Técnicas modal) and `abrirEscala()`/`abrirPassagemTurno()`/`abrirCentralCallback()` (external links) remain defined inline in `index.html`'s own `<script>` blocks — they have no JS-file counterpart and are not duplicated.

Several files rely on the browser's implicit global bindings for elements with an `id` (e.g. `ramal.value` instead of `document.getElementById('ramal').value`) in older patterns — this means **removing or renaming an `id` that's referenced this way breaks the referencing script even if you only touched the HTML**. Before deleting/renaming any `id`, grep the `js/` folder for bare references to that identifier, not just `getElementById` calls.

**WhatsApp callback module** (`#callback`) is split across two files (manual entry of operator, incident and phone — no CSV import, by design):
- `js/mensagens.js` — message *content* only: `SAUDACAO_CALLBACK` ("Olá, aqui é a Energisa."), `MENSAGENS_CALLBACK` (the 23 manual-selection messages of the Central Callback Web 1.1.0, copied verbatim from its `js/modelos.js`, each `{grupo, label, prioridade, texto}`, ordered by subject then title, pt-BR) and `saudacaoPersonalizada()`. The 4 automatic Central messages (abertura/previsão/encerramento) are intentionally NOT included. Do not edit texts without updating the Central.
- `js/callback-whatsapp.js` — orchestration: builds the `<select>` with one bold `<optgroup>` per subject ("⚠ PRIORIDADE" on risk subtypes, like the Central), renders the text (`Referência do atendimento: <incidente>` appended, like the Central), applies the greeting to the personalized mode (`cbwComSaudacao`), normalizes the phone only to add DDI 55 (no mobile-only restriction), and opens WhatsApp Web exactly like the Central: `window.open("about:blank", "_blank")` inside the click, `opener = null`, then navigates to `https://web.whatsapp.com/send?phone=55…&text=…`. Never use `wa.me`/`api.whatsapp.com` (they show an intermediate page and caused a second tab). Opening the chat does not send anything.
- `js/callback-whatsapp.test.js` — Node tests for the above.

The old message history (`js/storage.js`, `js/historico.js`, its UI and CSS) was removed. On init the module removes only the obsolete key `localStorage["coi_callback_whatsapp_historico"]`.

## ARMAZENAMENTO ATUAL

The Callback WhatsApp module persists nothing. Other modules use their own keys (e.g. `coi_demo_db_v1` for the demo backend, `coi_auth_sessao_demo` for the demo login) — never clear the whole `localStorage`. No backend, no database; data lives only in the browser that created it.

## AUSÊNCIA DE BACKEND / BANCO

There is no backend, no API, no server process (Node/Python/FastAPI/Express/etc.), and no database of any kind. No `package.json`, no build tooling, no dependencies. "Deploying" this app today means opening `index.html` or copying the folder to any static file host — there is no pipeline.

## Design system (CSS)

**Dark corporate theme (visual modernization, branch `feat/modernizacao-visual`).** `styles.css` is organized in numbered sections (tokens, base, layout, sidebar, collapsed sidebar, top bar, cards, forms/buttons, modals/toast, footer, Leaflet chrome, responsive). Tokens in `:root`: very dark navy surfaces (`--bg`, `--surface` opaque, `--surface-alt`, `--surface-raised` for modals/popups, `--surface-glass` for the main `.container` cards over the Christmas photo, `--input-bg`), text `--text`/`--text-secondary`/`--text-muted`, electric blue `--accent` (text/indicators on dark) vs `--accent-strong` (fill of buttons with white text — use this one for filled buttons, `--accent` fails contrast there), orange `--laranja` for small details only, plus layout tokens `--sidebar-width` (switches to `--sidebar-width-recolhida` under `html.sidebar-recolhida`), `--footer-height`, `--topbar-height`, `--content-pad-x`. `color-scheme: dark` makes native selects/scrollbars dark. Module stylesheets (`css/*.css`) use the same tokens with fallbacks; `css/auth.css` also styles the top-bar user block.

Layout: `.content` starts with a sticky `<header class="topbar">` (module breadcrumb `#topbar_trilha` / `#topbar_modulo`, filled by `js/layout-ui.js`, and the user block `#auth_usuario_badge` with `#auth_usuario_nome`, `#auth_btn_meu_perfil`, `#auth_btn_sair` — moved from the footer, same ids, still driven by `js/auth.js`). The fixed `<footer class="footer-global">` contains ONLY the signature "Desenvolvido por **Thiago Araújo** | COI SERGIPE" with a lock icon — no status, clock, user or buttons; keep it that way. The sidebar's bottom area is only the collapse button `#sidebar_btn_recolher`. `css/fundo-natal.css` follows `--sidebar-width` and `--footer-height`, so changing either keeps the Christmas photo framed to the visible area.

Leaflet's CSS loads after `styles.css`, so theme overrides for popups/zoom controls are prefixed with `.leaflet-container` to win on specificity. The map heights in `css/mapa.css` / `css/mapa-regional.css` (`calc(100vh - Npx)`) are calibrated for top bar + compact footer; recalibrate them if either changes.

A number of CSS classes are toggled directly by JS at runtime and must keep their exact names even when restyled: `.module`/`.active` (module + sidebar nav), `.aberta` (menu category), `body.modo-tela-ampla` (Equipes hides the sidebar), `html.sidebar-recolhida`, `.cbw-campo-erro`, `.cbw-preview-vazio`, `.cbw-bolha-vazia`, `.login-view.ativo`, `.mostrar` (login messages, user block), `#modal-mapa` / `#modalTabela` / `.modal` display toggling. When restyling, change values, not selector names. The global `button:hover` only recolors class-less (generic primary) buttons, so module buttons keep their own backgrounds.

## Icons

Icons are hand-authored inline SVG (feather-style line icons, `stroke="currentColor"`, no external icon font/CDN) rather than emoji, applied via the `.menu-icon` (sidebar nav) and `.btn-icon-svg` (inline in action buttons) size classes. A few emoji remain intentionally in generated *content* (toast messages, copied report text) — those are message content, not UI icons, and are out of scope for icon-consistency work.
